# strata-proxy

Hardened Cloudflare Worker for Strata Studio terrain tiles and bounded OpenStreetMap feature requests. The static app remains on Cloudflare Pages; `web/public/og.png` remains a static Pages asset and is not generated by this Worker.

## Routes

| Route | Upstream | Successful cache policy |
| --- | --- | --- |
| `GET /terrain/{z}/{x}/{y}.png` | Mapzen/Tilezen Terrarium tiles on AWS Open Data | 30 days at the edge, one day in browsers; 404s cache for one hour |
| `GET /overpass?south=40.7500&west=-73.9900&north=40.7600&east=-73.9800` | Fixed server-built query sent to `overpass-api.de`, then one Worker-side mirror retry | One day at the edge with one day stale-while-revalidate |
| `GET /health` | none | `no-store` |

`/overpass` does not accept Overpass QL. It accepts exactly `south`, `west`, `north`, and `east`, in that order, with four decimal places. Coordinates must be Web Mercator-safe, strictly ordered, at most 25 km², and no more than 25 km along either edge so thin polar strips cannot bypass the area bound. Aliases, duplicate/unknown parameters, alternate order, exponent notation, encoded punctuation, and noncanonical decimals are rejected. The Worker constructs the only permitted Overpass JSON program with a 15-second query timeout, a 16 MiB result cap, and the building, highway, water, waterway, coastline, and water-relation classes used by Strata Studio.

Terrain accepts no query parameters and only canonical decimal tile paths (no leading-zero aliases). Unknown paths and query parameters are rejected before any upstream request.

## Required variables and safe defaults

The committed `wrangler.jsonc` deliberately fails closed:

```json
{
  "ALLOWED_ORIGINS": "http://localhost:5173",
  "TERRAIN_ENABLED": "true",
  "OVERPASS_ENABLED": "false",
  "OVERPASS_PROTECTION_STAGED": "false",
  "BUILD_ID": "local"
}
```

- `ALLOWED_ORIGINS` is a comma-separated list of exact HTTP(S) origins. Wildcards, paths, credentials, and prefix matching are not accepted. Production must replace the localhost value with the exact Pages/custom-domain origin; preview origins must be listed explicitly if needed.
- `TERRAIN_ENABLED` and `OVERPASS_ENABLED` are emergency route switches. Only the literal value `true` enables a switch.
- `OVERPASS_PROTECTION_STAGED` is the operator attestation that route-specific Cloudflare edge protection has been staged and tested. The route is effective only when both Overpass values are `true`.
- `BUILD_ID` is optional public health metadata and is restricted to a short identifier. Do not put credentials or private environment data in it.

`OVERPASS_ENABLED` must remain `false` until a Cloudflare route-specific rate-limit or WAF rule for `/overpass` is configured, staged, and observed. The account capability is currently unverified. This repository intentionally does not implement a process-local/global in-memory limiter: Worker isolates do not provide reliable global coordination, so such a limiter would give false protection.

## CORS and failures

Requests with an `Origin` header are accepted only when the value exactly matches `ALLOWED_ORIGINS`. Successful CORS responses reflect that exact origin, include `Vary: Origin`, and expose only `Retry-After` and `X-Request-ID` for browser diagnostics/backoff. Route-aware preflight accepts only `GET` and the optional `Content-Type` request header. Requests without `Origin` remain available for health checks and server-side diagnostics but do not receive `Access-Control-Allow-Origin`.

Transient failures use deterministic JSON with a request ID and `no-store`:

```json
{
  "error": {
    "code": "upstream_unavailable",
    "message": "upstream is unavailable"
  },
  "requestId": "..."
}
```

Statuses 429, 502, 503, and 504 include a bounded `Retry-After`. Upstream request signals inherit caller aborts, per-upstream deadlines, and whole-route deadlines through complete body consumption. Overpass responses receive long cache headers only after a bounded 200 body has a JSON media type, valid JSON syntax, the required `elements` array, and client-safe element shapes. Terrain 200s must be bounded, structurally valid 256×256 PNGs; cached 404s discard upstream error bodies.

Logs contain only `requestId`, route, fixed upstream label, status, duration, and retry count. URLs, origins, bbox values, queries, bodies, and upstream response payloads are not logged.

## Health

`GET /health` reports only the sanitized public build ID, public bbox limits, and effective route states. It does not reveal the origin allowlist or the individual Overpass request/protection flags. A configuration that requests Overpass without the protection attestation returns 503 while the route itself remains disabled.

## Web integration

Production web builds still require the full route URLs:

```bash
VITE_TERRAIN_TILE_URL=https://<proxy-origin>/terrain
VITE_OVERPASS_URL=https://<proxy-origin>/overpass
```

The terrain loader appends `/{z}/{x}/{y}.png`. The Overpass loader snaps nearby bounds, formats the four canonical parameters, and tries the proxy once. The browser keeps that attempt alive through the Worker's two bounded upstream attempts; if it still fails, the browser retains one bounded direct POST against a distinct provider under the same total operation deadline. It validates status, `Retry-After`, media type, JSON syntax, and the required `elements` array before converting or writing IndexedDB cache data.

## Deployment staging

Do not add account IDs or credentials to source or documentation. When deployment is separately authorized:

1. configure an exact production origin allowlist;
2. leave Overpass disabled and deploy/health-check terrain;
3. create and stage the route-specific Cloudflare rate-limit/WAF rule for `/overpass`;
4. verify the rule with Overpass still disabled;
5. set `OVERPASS_PROTECTION_STAGED=true`, then set `OVERPASS_ENABLED=true`;
6. verify `/health`, structured failures, cache headers, and browser proxy-first/fallback behavior.

`limits.cpu_ms` remains absent for free-plan compatibility. The Worker buffers only bounded terrain/Overpass success bodies long enough to validate cache eligibility and does not use `caches.default`.
